# TASK-105 — Нативный ресайз с кастомной шапкой: корень проблемы и решение

Дата: 2026-11-17. Версия: 0.46.54.

## Постановка

«Ресайз окон — больная тема проекта. До сих пор никто не может решить эту проблему. Ты найди решение.»

Ограничения, подтверждённые автором: кастомная шапка остаётся; все окна (главное,
чтения, настройки; редактор — по решению TASK-104 системным); без acrylic/Mica;
без новых зависимостей не обязательно — но по итогам исследования они не понадобились
(см. «Решения», пункт про decorum).

## Почему не получалось: цепочка причин по исходникам tao 0.37.1 / wry 0.57.0 / tauri-runtime-wry 2.12.1

1. **Системный модальный цикл работает с частотой мыши, а не кадров.**
   `WM_NCLBUTTONDOWN` (его посылает `startResizeDragging`/`startDragging` из tao,
   `handle_os_dragging`) запускает цикл Windows, который присылает `WM_SIZE`/`WM_MOVE`
   на каждое событие указателя: 125–1000 Гц у обычных мышей.
2. **На каждое такое событие wry делает дорогую работу.** `parent_subclass_proc`
   в wry (src/webview2/mod.rs): на `WM_SIZE` — `ICoreWebView2Controller::SetBounds`
   **плюс** `SetWindowPos` дочернего HWND; на `WM_MOVE`/`WM_MOVING` —
   `NotifyParentWindowPositionChanged`. Сверху tauri-runtime-wry на каждый
   `Resized` вызывает `webview.set_bounds` ещё раз — двойная работа.
   WebView2 (Chromium) не успевает перестраивать композитор: окно «думает»
   и отстаёт от курсора. Это и есть медленность «того самого системного цикла»
   из TASK-099, и тормозы нативного `startDragging` из TASK-081.
3. **Ручной режим (TASK-099/102) лечил симптом.** rAF + `set_window_rect`
   ограничил частоту до 60 Гц — стало лучше, но добавился лаг IPC и потерялись
   Snap/минимальный размер. TASK-104 доказал: узкое место — «перестройка WebView2
   на каждый новый размер», а не IPC. Значит, победить можно только уменьшив
   частоту вызовов put_Bounds (нативно!) — что и делает дроссель.
4. **Почему у undecorated-окон «полоса ресайза в невидимой зоне тени»** (TASK-102/103):
   tao для undecorated+shadow в `WM_NCCALCSIZE` утапливает клиентскую область
   на величину теневых полей — полоса ресайза попадает за видимый край окна.

## Решение

**Три слоя, все — без новых зависимостей.**

1. **Нативный контроль потока.** Все окна создаются обычными окнами Windows
   (`decorations: true`, `resizable: true`). Ресайз и драг запускаются из JS
   одной командой на жест (`startResizeDragging`/`startDragging`), дальше всю
   геометрию считает Windows: минимальный размер — через `WM_GETMINMAXINFO`
   (из `minWidth`/`minHeight`), примагничивание, Aero Snap, `Win+стрелки`,
   восстановление развёрнутого окна за шапку.
2. **Скрытая рамка — кастомная шапка остаётся.** Новый модуль
   `src-tauri/src/borderless.rs` сабклассирует окно (`SetWindowSubclass`,
   comctl32 — тот же механизм, что у wry) и на `WM_NCCALCSIZE` возвращает 0:
   клиентская область занимает всё окно, системного заголовка не видно.
   Приём Windows Terminal и Chromium. Развёрнутое окно ограничивается рабочей
   областью монитора (иначе контент уйдёт под панель задач), автоскрытие
   панели учтено. На Windows 11 убирается системная обводка
   (`DWMWA_BORDER_COLOR = DWMWA_COLOR_NONE`); на Win10 вызов безвредно
   вернёт ошибку.
3. **Дроссель внутри модального цикла — лечит корневую причину.** Тот же
   сабкласс первым видит каждое сообщение (установлен позже wry — вызывается
   раньше) и внутри `WM_ENTERSIZEMOVE…WM_EXITSIZEMOVE` пропускает вниз по
   цепочке `WM_SIZE`/`WM_MOVE`/`WM_MOVING` не чаще ~120 Гц; промежуточные
   глотает, финальные размер и позиция доносятся на выходе из цикла и
   таймером-подстраховкой. Это rAF-бэкспрешер из TASK-102, перенесённый
   в нативный слой: WebView2 обновляется с кадровой частотой, а не с мышиной.

Ручки `.win-resize` и их подсветка остались прежними — теперь это только
триггеры `startResizeDragging`. Класс `body.resizing` (CSS гасит переходы)
ставится и снимается Rust-ом на входе/выходе из модального цикла — то же
самое, что раньше делали JS-ручки, но теперь и для `Win+стрелки`.

**Почему не tauri-plugin-decorum** (рассматривался по итогам обсуждения):
по исходникам v1.1.0 на Windows это `set_decorations(false)` + инжект
JS-шапки с `data-tauri-drag-region` (тот самый тормозящий `startDragging`
без дросселя) + HTML-кнопки; «Snap Layouts» там — симуляция нажатия Win+Z
через enigo. Ни дросселя, ни скрытой рамки — проблему он не решает.

**Окно редактора** осталось системным (решение TASK-104), но флаги создания
в v0.46.53 фактически не были переключены: окно создавалось с
`decorations: false, resizable: false`, при этом его хром был удалён —
без рамки, без ресайза, без рабочих кнопок. Исправлено: `decorations: true,
resizable: true`.

## Сделано

- `src-tauri/src/borderless.rs` — новый модуль: сабкласс, `WM_NCCALCSIZE → 0`
  (с рабочей областью для развёрнутого окна), дроссель `WM_SIZE`/`WM_MOVE`/
  `WM_MOVING` в модальном цикле, финальный флеш, `DWMWA_BORDER_COLOR`.
- `src-tauri/src/lib.rs` — `pub mod borderless`; главное окно
  `decorations(true)`, `resizable(true)`, `visible(false)` + `borderless::apply`
  до показа (не мигнёт системной шапкой; при ошибке — запасной вид с рамкой);
  удалена команда `set_window_rect`.
- `src-tauri/src/commands/mod.rs` — команда `apply_borderless(app, window, label)`:
  без `label` — окно-отправитель, с `label` — дочернее окно до показа.
- `src/main.ts` — `addResizeHandles` упрощена до `startResizeDragging(dir)`
  (одна команда на жест); `enableWindowDrag` — нативный `startDragging`;
  окна чтения/настроек: `decorations: true`, `resizable: true`, `visible: false`
  + `apply_borderless` до `show()`; окно редактора: `decorations: true`,
  `resizable: true`; удалены `set_window_rect`, импорт `PhysicalPosition`.
- `src/styles.css` — удалён мёртвый `body.win-drag` (ручной драг больше
  не ставит класс).
- Версия 0.46.54 в `tauri.conf.json`, `Cargo.toml`, `package.json`; CHANGELOG.

## Проверено

- `npx tsc --noEmit` — без ошибок (в окружении подготовки патча).
- `npm run build` (tsc + vite) — код возврата 0.
- Rust-часть собрана по образцам: FFI-подписации и структуры сверены с
  `wry 0.57.0` (`parent_subclass_proc`, `SetWindowSubclass`/`DefSubclassProc`),
  `tao 0.37.1` (`WM_NCCALCSIZE` для развёрнутого окна и автоскрываемой панели)
  и `main.rs` проекта (стиль raw-FFI). Локальной Windows-сборки в этом
  окружении нет — сборка и прогон на вашей машине.

## Осталось (живая проверка на Windows)

1. `npm install`, `npm run tauri build` (или dev) — сборка должна пройти
   без предупреждений clippy.
2. Главное окно: системной шапки нет, наша — на месте; тень есть; ресайз
   за края/углы идёт за курсором без «думания»; `Win+←/→` и `Win+↑`
   примагничивают; двойной клик по шапке разворачивает; развёрнутое окно
   не уходит под панель задач.
3. Окно чтения и настройки: то же самое; рамка не мигает при открытии.
4. Окно редактора: один системный заголовок, ресайз за край, кнопки внизу видны.
5. Перетаскивание за шапку: без отставания; Aero Snap при драге к краям.
6. Если на очень тяжёлом письме останется лёгкий подлаг при ресайзе окна
   чтения — следующий шаг из TASK-104: `body.resizing #body-frame
   { visibility: hidden }` (скрывать iframe письма на время жеста).
7. Откат при проблеме с драгом: вернуть тело `enableWindowDrag` из TASK-081
   (дроссель WM_MOVE при этом можно оставить). Откат всего решения: убрать
   `borderless::apply`/`apply_borderless` — окна останутся системными.

## Чек-лист рисков (что может пойти не так и почему принято)

- **Windows 10**: возможна волосная линия 1 px сверху у неразвёрнутого окна
  (артефакт `WM_NCCALCSIZE → 0`, тот же у Windows Terminal). На Win11 не
  проявляется.
- **Snap Layouts (меню раскладок по наведению на «развернуть»)**: недоступно —
  кнопка наша, HTML; системный flyout требует настоящего `HTMAXBUTTON`.
  `Win+Z` и все остальные пути работают. Возможное будущее улучшение —
  возвращать `HTMAXBUTTON` из сабкласса по координатам HTML-кнопки.
- **Alt+Space** открывает системное меню окна — штатно и полезно.
