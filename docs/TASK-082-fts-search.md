# TASK-082 — Поиск на FTS5

Дата: 2026-11-14. Версия: 0.46.37.

## Постановка

Из дорожной карты ускорения: поиск по почте был самым тяжёлым местом. `search_messages` выбирал из кэша **все письма всех папок** вместе с полными текстами тел (`LEFT JOIN bodies`), а затем сравнивал строки в Rust — обход нужен был потому, что SQLite `LOWER()` не понимает кириллицу, и «Тест» не находился по запросу «тест». На большом ящике это сотни миллисекунд и мегабайты лишних данных на каждый ввод (с debounce 250 мс).

## Решения

- Поисковый индекс FTS5: `messages_fts(subject, from_addr, body_text)`, токенизатор `unicode61 remove_diacritics 2` — регистр и кириллица обрабатываются самим SQLite.
- Индекс живёт рядом с кэшем (rowid = `messages.rowid`), а не в отдельной БД: поиск идёт join'ом к `messages`, папки фильтруются как раньше.
- Поддержка индекса: полная переиндексация папки при сохранении заголовков синхронизацией, точечное обновление `body_text` при сохранении тела, удаление строк при удалении письма/папки. Порядок важен: индекс чистится **до** удаления писем, потому что `INSERT OR REPLACE` выдаёт строкам новые rowid.
- Первый запуск после обновления: если в `meta` нет отметки `fts_ready`, индекс один раз собирается по уже скачанному кэшу.
- Запрос собирается из слов пользователя как префиксные фразы (`"слово"*`); всё, кроме букв и цифр, отбрасывается — так `*`, кавычки и дефисы не ломают синтаксис `MATCH`, а `ivan@mail.ru` превращается в три префикса и находит адрес.
- Флаг «совпало по телу» (`in_body`) считается по теме/отправителю: если там запроса нет — значит совпало по тексту письма.
