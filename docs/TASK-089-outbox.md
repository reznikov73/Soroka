# TASK-089 — Очередь исходящих: письмо не теряется без сети

Дата: 2026-11-15. Версия: 0.46.39.

## Постановка

Из дорожной карты: если сети нет, отправка просто падала с ошибкой, а текст оставался в редакторе. При работе с ноутбуком вне дома это значит «написал — и не отправил, пока не вспомнишь».

## Решения

- Письмо, которое не ушло по сетевой причине, **ставится в очередь** в SQLite (`outbox`) и уходит само, как только появится сеть.
- В очередь попадают только сетевые сбои: отказ авторизации, «неверный пароль» и прочие отказы сервера по-прежнему возвращаются ошибкой — иначе можно годами возить в очереди письмо, которое сервер не принимает.
- Хранится не готовое MIME-письмо, а всё необходимое для сборки: получатели, тема, текст, HTML и вложения в base64. При досылке письмо собирается заново тем же кодом, что и при обычной отправке — одно место правды для формата.
- Досылка привязана к успешной синхронизации: раз почта пришла, значит сеть есть. Проверка идёт в отдельном блокирующем потоке, чтобы не задерживать UI и синхронизацию.
- Порядок очереди — по id (старые первыми); при первой же сетевой ошибке цикл останавливается, чтобы не долбить сервер.
- В интерфейсе: тост «Сети нет — письмо в очереди, уйдёт при подключении» вместо ошибки; после успешной досылки приходит событие `outbox-sent`.

## Сделано

- `src-tauri/src/mail/store.rs` — таблица `outbox`, `queue_outbox`, `list_outbox`, `drop_outbox`, `mark_outbox_attempt`, `outbox_count`; тест `outbox_keeps_and_drops`.
- `src-tauri/src/commands/mod.rs` — `QueuedMail`/`QueuedFile`, `looks_like_offline()`, `flush_outbox()`, постановка в очередь внутри `send_mail`, вызов досылки после `sync_inbox`, поле `queued` в `SendReport`.
- `src/main.ts` — обработка `queued` в обычной отправке и во встроенном ответе.
