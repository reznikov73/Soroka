# TASK-090 — Мгновенные письма через IMAP IDLE

Дата: 2026-11-15. Версия: 0.46.40.

## Постановка

Из дорожной карты: новая почта появлялась только по таймеру (`check_interval_sec`, минимум 15 секунд) — на практике это означает задержку до минуты-двух и лишние полные синхронизации. Нужно, чтобы письмо появлялось сразу после прихода, как в веб-клиенте.

## Решения

- **Отдельное соединение на ящик.** IDLE занимает сессию целиком, поэтому он не может делить соединение с обычной синхронизацией. Каждый ящик получает свой поток; при выключенном тумблере потоки не создаются вовсе.
- **Тумблер в настройках, по умолчанию выключен** (`ui.idle_enabled`). Причина: IDLE у разных серверов ведёт себя по-разному (Яндекс, mail.ru, Gmail), а проверить это можно только на живом ящике. Выключенный тумблер = прежнее поведение, ничего не ломается.
- **Переиздание IDLE каждые 2 минуты** вместо 29 по RFC. Так настройка выключается за пару минут, а не через полчаса, и соединение не «умирает» молча на серверах с коротким inactivity-timeout.
- **Любое событие сервера — сигнал обновиться.** Не разбираем, что именно пришло (новое письмо, удаление, смена флагов): синхронизация всё равно перечитывает состояние папки. Это устойчивее, чем угадывать варианты ответов разных серверов.
- **Три сбоя подряд — поток выходит.** Остаётся обычный опрос по таймеру, в журнал пишется предупреждение. Никаких бесконечных реконнектов.
- **Фронтенд** слушает событие `mail-arrived`, обновляет список не чаще раза в 3 секунды и только для своего ящика; для чужого — просто обновляет счётчики.

## Сделано

- `src-tauri/src/mail/imap.rs` — `idle_watch()`: сессия, `select("INBOX")`, цикл IDLE с таймаутом 120 с, вызов `on_change` на событие.
- `src-tauri/src/commands/mod.rs` — `start_idle_watch()` (поток на ящик, backoff, проверка настройки перед каждым переизданием).
- `src-tauri/src/settings.rs` — поле `idle_enabled` (serde default, по умолчанию `false`).
- `src-tauri/src/lib.rs` — запуск при старте и регистрация команды.
- `src/main.ts` — обработка `mail-arrived`, тумблер `opt-idle` и вызов `start_idle_watch` при включении.
- `index.html` — чекбокс в настройках с честным предупреждением про отдельное соединение.

## Осталось

- Живая проверка: включить тумблер в настройках, отправить себе письмо с другого адреса — оно должно появиться в списке в течение нескольких секунд, без нажатия «Проверить почту».
- Если сервер не поддерживает IDLE или рвёт соединение — в журнале будет `idle <ящик>: ...`, поток остановится, поведение вернётся к таймеру.
- Следующая крупная задача дорожной карты: цепочки писем (`In-Reply-To`/`References`).
