# TASK-005 — Тело письма: безопасный HTML-просмотр + кэш тел в SQLite

**Цель:** клик по письму показывает его содержимое (текст или безопасно отрендеренный HTML);
тела сохраняются в SQLite и доступны офлайн; загрузка — ленивая (только по клику).

**Крейты (эта задача):** `mail-parser = "0.11"` (разбор MIME: text/html-части, кодировки,
base64/quoted-printable) и `ammonia = "4"` (санитизация HTML в Rust).

**Решение по данным (утверждено владельцем):** тела писем храним в SQLite.

## Поведение

1. Клик по письму → в панели справа под заголовком появляется тело:
   - есть HTML-версия → безопасный HTML (санитизирован `ammonia`, показ в sandbox-iframe);
   - только текст → блок обычного текста.
2. Первый показ — загрузка с сервера (IMAP `BODY.PEEK[]` — без пометки «прочитано»);
   повторный — мгновенно из кэша, в том числе офлайн.
3. Офлайн и тела нет в кэше → понятное сообщение в панели («нет сети, тело ещё не загружалось»),
   приложение живо.
4. Безопасность: скрипты и опасные атрибуты вычищаются (`ammonia`); **внешние картинки
   заблокированы** (не сливаем «что вы читаете» и не тормозим) — остаётся alt-текст.
5. Лёгкость: тело грузится только по клику; в памяти — одно активное тело; тело > 512 КБ
   сохраняется/показывается усечённым с пометкой.

## DoD

- [ ] `mail/body.rs`: `fetch_body(cfg, folder, uid)` (mUTF-7 для папки) → `mail-parser`;

      cp1251, base64; санитизация (script/onerror вычищаются, `<b>` остаётся).

      защита от гонок при быстрых кликах (счётчик запросов).
- [ ] Все проверки: `cargo build/test/clippy -D warnings/fmt --check`, `npm run build` — чисто;
      всего тестов ≥ 18.
- [ ] Живые: реальные письма (чек «ООО ИНТЕР», рассылка ig-store, Альфа-банк) читаются;

## Не входит

  исходный код письма целиком.
