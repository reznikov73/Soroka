# TASK-031 — «битое» письмо в папке и активация ящика

Версия: **0.29.1**. Дата: 2026-10-20.

## 1. «Не удалось обновить папку «Drafts»: [UNAVAILABLE] FETCH message 1 uid 2»

Симптом (из скриншота и лога): папка Drafts ящика `russiaimperia@yandex.ru` не загружалась, тост «Не удалось обновить папку…», в логе
`ERROR sync_folder 4::Drafts: … [UNAVAILABLE] FETCH message 1 uid 2: failure due to backend error`.

Причина: Яндекс отдаёт ошибку на FETCH диапазона из-за одного конкретного письма (uid 2), а клиент запрашивал папку одним FETCH — ошибка на письме убивала загрузку всей папки.

Исправление (`src-tauri/src/mail/imap.rs`):
- `fetch_range_resilient` — загрузка блоками по 25 писем; ошибка блока не роняет остальные;
- `fetch_bisect` — проблемный блок делится пополам, пока не находится конкретное письмо; оно пропускается с `WARN FETCH 1:1: письмо не отдаётся сервером`, остальные загружаются;
- после ошибки — короткий `NOOP` для сверки состояния сессии; общий бюджет 40 FETCH, чтобы «битая» папка не превращалась в сотню запросов;
- догрузка непрочитанных: при ошибке на набор UID — по одному письму;
- если сервер не отдал ни одного письма — прежняя ошибка (папка показывает кэш).

Проверка на живом Яндекс-ящике (v0.29.1):

```
11:45:30 WARN FETCH 1:5: сервер ответил ошибкой — … [UNAVAILABLE] FETCH message 1 uid 2 …
11:45:34 WARN FETCH 1:1: письмо не отдаётся сервером — No Response: [UNAVAILABLE] FETCH Completed …
11:45:34 WARN Drafts: пропущено писем — 1
11:45:34 INFO sync_folder 4::Drafts: всего 5, загружено 4
```

В окне: папка «Drafts» открылась, 4 письма в списке, статус «почта: папка «Drafts», писем 5», тоста об ошибке нет (`t291-5-drafts2.png`).

Ограничение: пропущенное письмо (uid 2) не отдаёт сам сервер — в списке его не будет, пока Яндекс не починит бэкенд.

## 2. Активация ящика не с первого клика

Две причины:
- в настройках `openSettings` вызывал `switchSettingsView("account")` до присваивания `editingAccountId`, поэтому подсветка строки считалась по старому ящику — визуально «первый клик не сработал». Теперь `editingAccountId` выставляется до переключения вида.
- в дереве папок `activateAccount` перерисовывал дерево только после ответа сервера (`get_folders`) и синхронизации — при медленном IMAP клик выглядел «непринятым». Теперь дерево сразу перерисовывается по кэшу (`renderFolders(lastFolders)`), данные подставляются по приходу.

Проверка: клик по `russiaimperia...` — через 300 мс ящик раскрыт и «Входящие» выбраны (`t291-2-switch-fast.png`); клик по `rez@poson.ru` в настройках — строка подсвечена и карточка открыта с первого раза (`t291-6-settings-click.png`).
