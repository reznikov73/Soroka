# TASK-107 — Простой режим окон: системная рамка без нашего кода в цикле

Дата: 2026-11-18. Версия: 0.46.56. База: `8e72394` (0.46.55).

## Постановка

После 0.46.54 (нативный ресайз с дросселем) и 0.46.55 (откат + заморозка содержимого) окна всё равно медленно двигаются и растягиваются. Решение владельца: перейти на «простой интерфейс» — обычные системные окна Windows без кастомной шапки и без наших механизмов в цикле ресайза. Красивости жертвуем ради скорости.

## Решения

1. **Все окна создаются обычными окнами Windows**: `decorations: true`, `resizable: true` — главное (Rust, `lib.rs`), настройки, чтение (JS). Окно редактора уже такое с 0.46.54. Геометрию, минимальный размер (`WM_GETMINMAXINFO`), Aero Snap, `Win+стрелки`, свёртывание и перетаскивание ведёт система. Путь сообщений — ровно как у любого нативного приложения с WebView2 (Edge, Teams): `WM_SIZE` → wry двигает дочерний HWND. Ни сабклассов, ни дросселей, ни IPC в цикле.

2. **Ручной движок удалён целиком, а не отключён**: JS-ручки `.rz-*` с расчётом прямоугольника, команда `set_window_rect`, ручной драг `enableWindowDrag` через `setPosition`, драг заголовка настроек, `body.resizing`/`body.win-drag` классы и заморозка `content-visibility` из TASK-106 (её ставил только удалённый движок). Мёртвый код не копим.

3. **Кастомные кнопки окна удалены**: `#win-min`/`#win-max`/`#win-close` из `index.html`, их обработчики и CSS. В окнах-спутниках (чтение, настройки, редактор) наша шапка `#titlebar` скрыта: системный заголовок показывает тему письма/название. В главном окне `#titlebar` остаётся как панель инструментов (поиск, сортировка, кнопки) — под системным заголовком.

4. **Сохранение размера окна чтения задебаунсено** (400 мс): при системном ресайзе `Resized` приходит с частотой мыши, и писать `localStorage` + IPC на каждое событие незачем.

### Известные компромиссы

- Системная кнопка «Свернуть» сворачивает в панель задач; настройка «сворачивать в трей» действует только на закрытие (перехват `onCloseRequested` сохранён).
- Двойной клик по нашей панели инструментов больше не разворачивает окно — это делает двойной клик по системному заголовку.
- Внешний вид: системная полоса заголовка над нашей панелью инструментов в главном окне.

## Сделано

- `src-tauri/src/lib.rs` — главное окно `decorations(true)`, `resizable(true)`; удалены команда `set_window_rect` и её регистрация.
- `src/main.ts` — окна настроек и чтения `decorations: true`, `resizable: true`; удалены `addResizeHandles`, `enableWindowDrag`, `initWindowDrag`, `initSettingsWindowChrome`, `initReaderWindowChrome`, обработчики `#win-min`/`#win-max`/`#win-close` и двойного клика; `makeSettingsMovable` в отдельном окне больше не двигает окно; `initReaderGeometry` задебаунсен; убран импорт `PhysicalPosition` (−268 строк).
- `index.html` — удалены кнопки `#win-min`/`#win-max`/`#win-close`.
- `src/styles.css` — удалены ручки `.rz-*`/`.win-resize` всех окон, стили кнопок окна, `body.resizing` (переходы и заморозка TASK-106), `body.win-drag`; шапки окон-спутников скрыты; оверлей настроек на всю высоту (−80 строк).
- Версии: `tauri.conf.json`, `Cargo.toml`, `Cargo.lock`, `package.json` → 0.46.56.

### Осталось (Windows, у владельца)

- `cargo clippy --all-targets -- -D warnings`, `cargo test`, `npm run tauri build`.
- Живая проверка скорости: тянуть край и заголовок каждого окна — окно должно идти за курсором как в Блокноте; Aero Snap, `Win+стрелки`, двойной клик по заголовку, минимальные размеры.
- Крестик/закрытие главного окна при включённой настройке «в трей» — окно прячется, выход через трей.
- Если и теперь тянется медленно — узкое место не наша шапка и не наш цикл, а перестройка DOM списка/письма в WebView2; тогда следующий шаг — виртуализация списка (TASK-078 углублять) или обрезка тяжёлых стилей (backdrop-filter, box-shadow строк).

## Откат
