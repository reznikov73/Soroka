# TASK-052 — окно настроек: причина и исправление

Версия: 0.46.5. Дата: 26.10.2026.

## Причина
Окно настроек создавалось, но оказывалось позади главного. Главное окно уже было заблокировано через setEnabled(false), поэтому клики по заголовку и крестику уходили в заблокированное главное окно: визуально «окно не реагирует».

Дополнительно в 0.46.3 метка `settings` не совпадала с ACL-шаблоном `settings-*`, из-за чего окно могло вообще не создаваться.

## Исправление
- Метка снова уникальная: `settings-<timestamp>`.
- Главное окно блокируется только после `tauri://created`.
- Окно настроек показывается, получает фокус и ставится `alwaysOnTop`, поэтому не уходит под главное.
- Добавлена обработка ошибки создания с разблокировкой главного окна.

## Проверка
- npm run build, cargo check, cargo tauri build; exe 7.55 МБ, установщик 2.86 МБ.
- UIAutomation: кнопка «Настройки» открыла окно; главное окно disabled=False, окно настроек enabled=True.
- UIAutomation: кнопка «Закрыть» закрыла настройки, главное окно снова enabled=True.
- Перетаскивание реальной мышью не проверено: синтетический mouse_event не создаёт pointermove в WebView2.
