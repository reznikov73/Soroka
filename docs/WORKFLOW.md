# Правила работы над POS Mail (soroka)

Зафиксировано: 2026-11-03. Этот файл — точка входа, чтобы продолжить работу в новой сессии.

## Где что лежит

| Файл | Назначение |
|---|---|
| `docs/WORKFLOW.md` | правила нашего рабочего цикла (этот файл) |
| `docs/TASK-NNN-<имя>.md` | постановка задачи, принятые решения, что изменено, как проверено |
| `docs/screenshots/` | снимки интерфейса для README |

Все служебные материалы — инструкции, правила, ТЗ, постановки задач, отчёты — пишутся **только в `docs/`**. Папка `tasks/`, упомянутая в README, не используется.

## 1. Перед выполнением задачи

1. Пересказать, как понята задача: что меняем, где, чего не трогаем.
2. Задать уточняющие вопросы, если есть развилки.
3. Начать кодировать только после явного разрешения пользователя.

## 2. После изменений — полный цикл

1. Правки кода.
2. Версия: patch (`0.46.5 → 0.46.6`) в `src-tauri/tauri.conf.json`; `scripts/sync-version.ps1` разносит её в `Cargo.toml` и `package.json`; новый раздел в `CHANGELOG.md`.
3. Сборка: `npm run tauri build` → `src-tauri/target/release/POSmail.exe` и `src-tauri/target/release/bundle/nsis/POS Mail_<версия>_x64-setup.exe`. Проверить, что оба файла созданы.
4. Коммит: `fix: vX.Y.Z — суть изменения (TASK-NNN)`.
5. Пуш: `git push origin main`, без PR.

Если сборка или проверки падают — не коммитить и не пушить: показать ошибку и ждать решения.

## 3. Нумерация и версии

- Задачи: `TASK-053`, `TASK-054`, … Последняя завершённая — `TASK-052`.
- Версии: SemVer, patch на каждое изменение.
- Основание версии — `src-tauri/tauri.conf.json`; `Cargo.toml` и `package.json` её повторяют.

## 4. Как продолжить в новой сессии

1. Прочитать `docs/WORKFLOW.md`.
2. Посмотреть последний файл `docs/TASK-*.md`.
3. `git log --oneline -5` и `git status` — понять, на чём остановились.
4. Дальше — по разделу 1.
