# TASK-026 — отчёт: Shift+клик, массовые действия в меню, подписи

## 1. Shift+клик выделял текст

Причина: список писем — обычный `ul`, браузер при Shift+клике выделял текст строки, а не диапазон писем.
Исправлено:
- CSS: `#messages { user-select: none; -webkit-user-select: none; }` — текст в списке больше не выделяется;
- `mousedown` с `shiftKey` → `preventDefault()` — гасит выделение до того, как оно начнётся.
Ctrl+клик, Shift+клик и Ctrl+A теперь работают как выделение писем.

## 2. Массовые действия в контекстном меню

Правый клик по строке, входящей в выделение (когда выбрано больше одного письма), открывает меню массовых действий:
- «В корзину (N)»,
- «Прочитано (N)», «Непрочитано (N)»,
- «⚑ Важное (N)», «Снять ⚑ (N)»,
- «Снять выделение».

Правый клик по невыделенной строке по-прежнему показывает обычное меню письма (Открыть, В корзину, Не спам, Прочитано/Непрочитано).

## 3. Подписи (как в The Bat!)

Раньше подписи только хранились в настройках и никуда не подставлялись — в подсказке честно было написано «вставка появится позже».
Теперь:
- при открытии нового письма, ответа и пересылки подставляется подпись по умолчанию (с галочкой, иначе первая);
- в окне письма над текстом появился селект «Подпись»: «Без подписи» или любая из списка; при смене старая подпись заменяется, текст письма сохраняется;
- при открытии черновика подпись не дублируется.

Макросы (как в The Bat!):
| Макрос | Значение |
|---|---|
| `%FromName` | имя отправителя (часть адреса до @) |
| `%FromAddr` | адрес активного ящика |
| `%ToName` | имя получателя из поля «Кому» |
| `%ToAddr` | адрес получателя |
| `%Subject` | тема письма |
| `%Date` | текущая дата, дд.мм.гггг |
| `%Time` | текущее время, чч:мм |
| `%Quote` | цитата исходного письма |
| `%Cursor` | место, где встанет курсор после вставки подписи |

Подсказка со списком макросов добавлена в «Настройки → Подписи».

- Подпись вставляется простым текстом (без HTML-форматирования), как и тело письма в текущей версии.

## 4. Бонус: логи сразу нашли баг с потерей кэша

При проверке лог показал:

```
ERROR sync_inbox 2: ошибка протокола IMAP: Bye Response: no explanation given
 INFO sync_inbox 1: всего 0, загружено 0
```

Сервер Majordomo рвёт соединение при частых синхронизациях (за час было много перезапусков). И тут же выяснилось: пустой ответ «0 писем» **затирал кэш INBOX** — `save_sync` удалял все письма папки и вставлял пустоту.

Исправлено: `save_sync` теперь проверяет, был ли кэш непустым, и при пустом ответе сервера возвращает ошибку, не трогая письма. Добавлен тест `empty_sync_keeps_cache`. Всего тестов: **65 passed, 1 ignored**.

Потерянный кэш восстановится при следующей успешной синхронизации — письма на сервере целы.

## 5. v0.26.1: папка «Спам» на Mail.ru не грузилась (`* BYE`)

Пользователь сообщил: при открытии «Спам» появляется «Не удалось обновить папку 2::Спам: сервер прервал соединение — показан кэш».

Что показала диагностика:

| Проверка | Результат |
|---|---|
| Python (`imaplib`): LOGIN + SELECT INBOX + FETCH 1:9 (UID ENVELOPE FLAGS BODYSTRUCTURE) | OK, 9 писем |
| Rust (`imap` crate), SELECT INBOX / SELECT «Спам» (MUTF-7) | OK, 9 писем |
| Rust, FETCH 1:9 с ENVELOPE | `Protocol("Bye Response: no explanation given")` |
| Rust, FETCH по одному | падает только `seq 4` |
| Rust, FETCH seq 4 с `BODYSTRUCTURE` или `RFC822.SIZE` | OK |
| Rust, FETCH seq 4 с `ENVELOPE` | BYE |
| Rust, FETCH 1:9 с `BODY.PEEK[HEADER.FIELDS (…)]` | OK, 9 писем |

Вывод: сервер Mail.ru рвёт соединение при сериализации ENVELOPE конкретного письма (повреждённый/нестандартный заголовок). Так как весь список тянулся одной командой, из-за одного письма падала синхронизация всей папки.

Исправление:
- `fetch_headers` больше не запрашивает `ENVELOPE`: `HEADER_QUERY = (UID FLAGS BODYSTRUCTURE BODY.PEEK[HEADER.FIELDS (FROM TO SUBJECT DATE)])`;
- добавлены `parse_header_fields` (разбор с учётом «сложенных» строк) и `header_from_fields` (сборка `MessageHeader` из полей заголовка, декодирование RFC 2047, извлечение имени/адреса через `contacts::extract_name`/`extract_email`);
- тест `parses_folded_header_fields`; всего **66 passed, 1 ignored**, clippy чист.

## 6. v0.26.2: диагностика папок и понятные сообщения

После 0.26.1 проверил все папки всех трёх ящиков. Выяснилось:

- Mail.ru (ящик 1) и Majordomo (ящик 3) в большинстве папок действительно пусты — кэш не терялся, сервер отдаёт 0.
- Папка `forward` у Majordomo отвечает на `SELECT` ошибкой `[SERVERBUG] Internal error occurred` — это баг сервера на конкретной папке, не клиента. Клиент показывал сырой текст протокола.

Сделано:
- `sync_folder` пишет в лог `INFO sync_folder <папка>: всего N, загружено M` и `ERROR sync_folder <папка>: <причина>` — раньше логировались только «Входящие», и по папкам не было видно ничего.
- Для серверных ошибок (`SERVERBUG`, `Internal error`) уведомление стало «сервер вернул ошибку на эту папку — показан кэш» вместо сырого `No Response: [SERVERBUG] …`.
- В уведомлении и статусе показывается короткое имя папки («forward»), а не ключ «3::forward».

Проверено вживую (v0.26.2): `sync_folder 1::INBOX/News: всего 0, загружено 0`; `ERROR sync_folder 3::forward: ошибка протокола IMAP: No Response: [SERVERBUG] …` и toast «Не удалось обновить папку «forward»: сервер вернул ошибку на эту папку — показан кэш»; приложение не зависает.
