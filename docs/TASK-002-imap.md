# TASK-002 — Почта: загрузка писем по IMAP («Сорока»)

**Исполнитель:** AutoClaw (AutoCoder). Перед началом прочитать навык `soroka-bootstrap` (разделы 1.1, 3, 6).
**Рабочая область:** `E:\Work\VSC\PostAi` · **Проект:** `E:\Work\VSC\PostAi\soroka`.
**Платформа:** ТОЛЬКО Windows 10+. IDE: VS Code.
**Окружение:** подготовлено (SKILL §1.1); перед cargo-командами активировать `. .\scripts\devshell.ps1`.
**Правило:** строго по этапам; каждый этап — `git add` + `commit` + `push`. Все файлы — UTF-8; `.ps1` — с BOM.

## Цель

Подключить «Сороку» к настоящему почтовому ящику по IMAP (тестовый: `reznikov_a@mail.ru`, сервер `imap.mail.ru:993`, SSL/TLS) и показать письма в интерфейсе: папки, список писем, детали выбранного письма. По завершении синхронизации — тост «Сорока на хвосте принесла — N писем».

## Нефункциональные требования

- imap-крейт синхронный: сетевые вызовы — только через `tokio::task::spawn_blocking`; UI не блокировать.
- Секретов в репозитории нет. Учётка: переменные окружения `SOROKA_IMAP_USER` / `SOROKA_IMAP_PASS` (приоритет), иначе локальный файл `%APPDATA%\Soroka\account.json` (вне репо):

```json
{
  "email": "reznikov_a@mail.ru",
  "password": "<пароль для внешних приложений>",
  "imap_host": "imap.mail.ru",
  "imap_port": 993
}
```

- Таймауты соединения; лимит загрузки — последние N писем (константа, по умолчанию 30).
- Ошибки сети/логина — понятный текст в UI, без паники. `unwrap()` — только в тестах.
- Существующее не ломаем: ping/app_info, версионирование, задачи VS Code, devshell.

## Бренд

- Тост при синхронизации: «Сорока на хвосте принесла — N писем» (фирменная фраза).
- Ошибки — в «сорочьем» тоне (например: «Сорока вернулась ни с чем: <причина>», «Сорока не долетела до ящика: <причина>»).

## Этапы

- **Этап 0 — Подготовка:** пароль для внешних приложений Mail.ru (владелец) → `%APPDATA%\Soroka\account.json`; разведка крейта `imap`.
- **Этап 1 — Зависимости и модуль:** `imap` (точная версия) + TLS; `mail/imap.rs`: `AccountConfig`, `load_account()`, `MessageHeader`, `fetch_inbox()` (connect → login → select → fetch заголовков), `list_folders()`.
- **Этап 2 — Мост в UI:** команды `sync_inbox`, `get_folders`, `get_messages`; состояние приложения (State); событие `sync-finished { count }`.
- **Этап 3 — Интерфейс:** папки / список / детали; кнопка «Проверить почту»; тост; статус-бар.
- **Этап 4 — Проверка и финал:** fmt/clippy/tsc; живой прогон; версия 0.2.0; CHANGELOG; коммиты; отчёт.

## Стоп-условия

- Mail.ru не пускает (IMAP выключен / неверный пароль) → точный текст ошибки + инструкция владельцу, остановиться.
- Крейт `imap`: если выбранная версия не собирается — зафиксировать проблему; не более 2 экспериментальных итераций с версиями.

## Владельцу (подготовка, 2 минуты)

1. Mail.ru → Настройки → Безопасность → «Пароли для внешних приложений» → создать (имя: Soroka).
2. Выполнить в PowerShell (подставить пароль вместо `ВСТАВЬТЕ_ПАРОЛЬ_ПРИЛОЖЕНИЯ`):

```powershell
New-Item -Force -ItemType Directory "$env:APPDATA\Soroka" | Out-Null
$json = '{"email":"reznikov_a@mail.ru","password":"ВСТАВЬТЕ_ПАРОЛЬ_ПРИЛОЖЕНИЯ","imap_host":"imap.mail.ru","imap_port":993}'
[IO.File]::WriteAllText("$env:APPDATA\Soroka\account.json", $json)
```
