# TASK-078 — Быстрый список: точечные обновления строк

Дата: 2026-11-13. Версия: 0.46.34.

## Постановка

Из дорожной карты ускорения (обсуждение 2026-11-13): список писем перерисовывается целиком на любое действие — открытие письма, отметку важности, приход ИИ-разбора, встроенный ответ. На папке в сотни строк это пересборка тысяч DOM-узлов ради одной строки: мигание, потеря hover, лишняя работа.

## Причина

`renderMessages()` очищает `innerHTML` и строит все строки заново; `messageRow()` создаёт ~15 узлов, 2 SVG и 5+ слушателей на строку. Горячие пути — `markSeen` (вызывается при каждом открытии письма), `toggleFlag`, `requestAnalysis`, тоггл встроенного ответа — звали полный рендер.

## Решения

- `refreshMessageRow(m)`: строка заменяется свежей копией себя из того же `messageRow()` через `replaceWith`. Разметка не расходится с полным рендером (один строитель), соседние строки и скролл не трогаются. Переходные классы (`selected`, `pending-del`, `pending-spam`) переносятся.
- `syncInlineReply()`: коробки `.inline-reply` убираются/добавляются на месте, без пересборки списка (открытие, «Отмена», отправка).
- Полный рендер вставляет строки через `DocumentFragment` — один reflow вместо n.
- `sortedMessages()` кэширует `messageTime` по `uid`: даты парсятся O(n), а не O(n·log n).
- CSS: `content-visibility: auto; contain-intrinsic-size: auto 52px` на `li.m-row` — невидимые строки не лэйаутятся и не красятся; `font-variant-numeric: tabular-nums` на `.m-time` — даты в колонку не «дышат».

## Сделано

- `src/main.ts` — `refreshMessageRow()`, `syncInlineReply()`, переключение горячих путей (`markSeen`, `toggleFlag`, `requestAnalysis`, inline-ответ, `undoSpam`), фрагментная вставка, кэш дат в сортировке.
- `src/styles.css` — `content-visibility` для строк, табличные цифры времени.
