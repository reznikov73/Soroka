# TASK-027 — выделение клавиатурой, отправка по списку адресов, черновики, адресная книга

Версия: **0.27.0**. Коммит: см. `git log`. Дата: 2026-10-19.

## 1. Shift+↑/↓ — выделение нескольких писем с клавиатуры

Было: модификаторы работали только с мышью; стрелки просто переносили выбор на соседнее письмо.

Сделано (`src/main.ts`):
- `moveMessageSelection(delta, extend)` — при `extend` (Shift) диапазон тянется от опорной строки (`lastAnchorUid`) до новой; набор `selectedUids` заменяется диапазоном, как в Проводнике.
- Опорная строка ставится при первом Shift+Arrow, дальше не смещается — Shift+↑ сжимает диапазон с той же стороны.
- Работает для `↑ ↓ Home End PageUp PageDown`.
- В `initKeyboardNav()` передаётся `e.shiftKey`.

Проверка: клик по первому письму в «Входящих» аккаунта 2, три раза Shift+↓ → «Выбрано: 3», подсвечены три строки (`t270-2-shift.png`).

Ограничение: Shift+клик мышью в WebView2 не эмулируется (модификаторы не доходят), проверено только клавиатурой.

## 2. Отправка падала: «плохой адрес получателя: Invalid email domain»

Причина: автодополнение вставляет `адрес, ` (с запятой и пробелом). В `build_message` строка уходила в `lettre::Address::parse` целиком, `trim()` убирал только пробел — оставалась запятая, домен `mail.ru,` считался невалидным. Ошибка воспроизводилась и при отправке, и при сохранении черновика.

Сделано:
- `smtp::parse_recipients(&str)` — режет по `,` и `;`, обрезает пробелы и кавычки, разбирает каждый элемент как `Mailbox` (понимает `Имя <адрес>`), отбрасывает дубли по адресу, требует хотя бы одного получателя.
- `build_message` собирает письмо на несколько адресов (`builder.to(...)` в цикле).
- Фронт: `normalizeRecipients()` — та же нормализация перед отправкой и перед сохранением черновика; при отправке поле «Кому» приводится к чистому виду.
- Тест `parses_recipient_list`: `"reznikov_a@mail.ru, "` → 1 адрес; `"a@b.ru; Имя <c@d.ru>"` → 2 адреса с именем; пустая строка и «не-адрес» → ошибка.

Проверка: письмо, отправленное из формы с адресом, выбранным из подсказки, ушло без ошибки (модалка закрылась, тоста об ошибке нет).

## 3. Черновик не сохранялся на сервер: «Folder does not exists»

Найдено при живой проверке после фикса адресов.

Причина: `find_drafts` возвращает папку из локального кэша, где имена хранятся с префиксом ящика (`2::Черновики`). Это имя уходило в `IMAP APPEND` после MUTF-7 — сервер отвечал `Folder does not exists`.

Сделано (`src-tauri/src/commands/mod.rs`):
- `save_draft`: имя папки нормализуется через `accounts::split_key(...).1` — на сервер уходит `Черновики`.
- `delete_draft`: то же для старой записи (`r.folder`), чтобы удаление старых черновиков тоже работало.

Проверка: «В черновики» → тост «Черновик сохранён», в форме «✓ сохранено 00:23» (`t270-7-draft2.png`).

## 4. Адресная книга: разбор и варианты

Собрано `DELIVERY/soroka-contacts-mockups.html` (в рабочей папке AutoCoder): как устроены контакты в Gmail, Outlook People, Apple Mail, Thunderbird, Superhuman + три варианта макета для Сороки:

- **A — три панели** (группы / список / карточка): привычно, но тесно в 1200 px.
- **B — сетка карточек** (Outlook People): красиво, но мало места под данные, нужен второй экран для правки.
- **C — палитра** (Superhuman): поиск + клавиатура + «из переписки», быстрее всего до «написать».
- **Рекомендация: C + A** — палитра как вход, три панели как расширенный режим по кнопке «Все контакты».
