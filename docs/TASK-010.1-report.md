# TASK-010.1 — Итоговый отчёт (устойчивость IMAP: автоповтор при `* BYE`)

**Статус:** выполнен, релиз 0.10.1. **Дата:** 2026-10-15. **Репозиторий:** https://github.com/reznikov73/Soroka (main).

## Симптом

При открытии папки «Спам» в приложении: «Не удалось открыть папку «Спам»: ошибка протокола IMAP:
Bye Response: no explanation given».

## Диагноз (наблюдения)

- Текст ошибки формируется крейтом `imap 3.0.0-alpha.15` при получении от сервера ответа `* BYE`
  (без пояснения) — источник: `client.rs` крейта, ветка `Status::Bye`.
- Точная последовательность приложения (SELECT «Спам» с закодированным mUTF‑7 именем `&BCEEPwQwBDw-`
  + `FETCH (UID ENVELOPE FLAGS)`) на сервере mail.ru выполняется успешно — проверено живым скриптом
  сразу после инцидента: select OK (32 письма), fetch OK.
- Значит: кодирование имён папок и логика корректны; сбой — временный разрыв соединения сервером
  (типично при частых/параллельных подключениях).

## Исправление

| Файл | Что сделано |
| --- | --- |
| `src-tauri\src\mail\imap.rs` | `with_session`: при ошибке‑разрыве (`Bye Response`, `Connection Lost`, io) — пауза 0,7 с и **ровно один повтор** на свежем соединении. Ошибки connect/login и «No»‑ответы не повторяются. Признак — новая ф‑я `is_disconnect_error` + юнит‑тест. |
| `src-tauri\src\mail\body.rs` | `fetch_raw` переведён на общий `with_session` (убран дублирующий сессионный код; повтор работает и для тел писем/вложений). |
| `src\main.ts` | Понятное сообщение при обрыве: «сервер прервал соединение — попробуйте ещё раз» (вместо технического текста). |
