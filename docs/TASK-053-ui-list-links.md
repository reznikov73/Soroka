# TASK-053. Плотный список, выделение строки, ссылки в письме

**Статус: готово, v0.46.6.** Промт для исполнителя: [TASK-053-prompt.md](TASK-053-prompt.md).
Отчёт: [TASK-053-report.md](TASK-053-report.md).
Все факты ниже проверены напрямую по коду (v0.46.5). Правки в код не вносились.

## 1. Плотный список писем не применяется

Чекбокс «Плотный список: одна строка на письмо» (Настройки → Оформление) включён, но список остаётся трёхстрочным: тема, отправитель, сводка ИИ.

- Механизм есть: `syncDenseClass()` — `src/main.ts:6050` вешает `dense-list` на `body`; `applyDensity()` — `src/main.ts:6055`; чекбокс `#opt-dense` — `src/main.ts:6104–6105`.
- Стили плотного режима: `body.dense-list #messages li.m-row` — `src/styles.css:2134–2152`.
- Причина-кандидат 1: в светлой теме правила `html[data-theme="light"] #messages li.m-row { padding: 9px 12px 9px 14px; }` — `src/styles.css:2394` и `2429` — идут позже при той же специфичности (1 id, 2 класса, 2 элемента) и перекрывают `padding` плотного режима.
- Причина-кандидат 2: окно настроек — отдельный webview (`?settings=1`, `src/main.ts:7210`); при закрытии шлёт `settings-changed` (`src/main.ts:5160`), но главное окно в обработчике (`src/main.ts:7321–7326`) не вызывает `syncDenseClass()` и не перерисовывает список — изменение применяется только после перезапуска.
- Третья строка — `.m-ai`, создаётся в `messageRow()` (`src/main.ts:4599–4604`) и в плотном режиме скрывается. Когда плотный режим реально применяется, третья строка исчезает — быстрый визуальный признак.

## 2. Текущую строку списка путают с непрочитанной

- Текущая строка: `.list li.selected { background: var(--accent-weak-2); box-shadow: inset 3px 0 0 var(--accent); }` — `src/styles.css:281`; класс ставится в `src/main.ts:4755`, `5032`.
- Непрочитанное: `html[data-theme="light"] #messages li.m-row.unread::before` — `src/styles.css:2430` — та же 3-пиксельная синяя полоса у левого края, отличие только в скруглении.
- Мультивыделение: `#messages li.m-row.multi` — `src/styles.css:1922–1925`, `2481–2482`.
- Сопутствующий баг: в `:root` (`src/styles.css:10,16,17,26,27,28`) токены `--hover`, `--surface1`, `--surface2`, `--accent-weak`, `--accent-weak-2`, `--accent-line` объявлены как `--x: var(--x)` — самоссылка, в тёмной теме они не работают.

## 3. Ссылки в теле письма не открываются

- Тело письма рендерится в `iframe`: `index.html:198` — `<iframe id="body-frame" ... sandbox="">`. Пустой `sandbox` запрещает навигацию и делает документ непрозрачным для родителя: нельзя даже навесить обработчик кликов.
- Контент собирает `wrapHtml()` — `src/main.ts:2021–2042`, подаётся через `srcdoc` — `src/main.ts:814`, `5296`, `7448`. Для ссылок задан только цвет, ни `target`, ни обработчиков нет.
- Плагин `@tauri-apps/plugin-opener` уже подключён, разрешение `opener:default` выдано (`src-tauri/capabilities/default.json`), но `openUrl` в коде не используется.
- Побочный факт: в письмах plain text ссылки не кликабельны вовсе (текст вставляется как `textContent`, `src/main.ts:820–829`). В объём TASK-053 не входит, зафиксировано отдельно.

## Приёмка

1. Плотный режим включается и выключается сразу, без перезапуска, в светлой и тёмной теме; высота строки 24–28 px.
2. На одном экране различимы три состояния: текущая строка, группа выделенных, непрочитанное. Контраст текста на выделенной строке ≥ 4.5:1.
3. Ссылка `https` открывается в браузере по умолчанию; `mailto` обрабатывается или корректно игнорируется; `javascript:` не выполняется; CSP письма не ослаблен.
4. `npm run build` в `soroka` проходит без ошибок.
