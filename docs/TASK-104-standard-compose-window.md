# TASK-104 — Окно редактора стало обычным окном Windows

Дата: 2026-11-17. Версия: 0.46.53.

## Что мы знаем к этому моменту

- Нативное перетаскивание окна по заголовку в WebView2 медленное — это выяснилось ещё в TASK-097, поэтому у всех окон своя шапка и ручной драг через `setPosition`.
- Ручное изменение размера (свой расчёт + `setSize`) осталось медленным даже после батча в одну команду и backpressure (0.46.52). Значит узкое место — не IPC и не количество вызовов, а **перестройка WebView2 на каждый новый размер**.
- Нативный ресайз (`WS_THICKFRAME` при `decorations: true`) выполняет сама Windows: окно меняет размер в своём цикле, без нашего участия в каждом кадре.

## Решение

Окно редактора письма переведено в **обычное окно Windows**: `decorations: true`, `resizable: true`, системная рамка и заголовок. Наша шапка в нём скрыта (`body.compose-window #titlebar { display: none }`), оверлей занимает всю высоту. Свои ручки и ручной драг для этого окна больше не создаются — функция `initComposeWindowChrome()` удалена.

Что сохранилось от предыдущих задач:
- CSS-грип карточки отключён (иначе снова тянулся бы DOM, а не окно);
- сброс inline `width/height` при открытии;
- раскладка формы: тело письма прокручивается, нижние кнопки всегда видны.

## Осознанный обмен

- **Плюс:** ресайз делает Windows, а не наш цикл; пропадает целый слой — своя шапка, восемь ручек, расчёт геометрии.
- **Минус:** перетаскивание за системный заголовок снова идёт системным путём. Для окна, которое открывается по центру и живёт недолго, это приемлемо; для окна чтения длинных писем — нет, поэтому там остаётся своя шапка и быстрый драг.

## Сделано

- `src/main.ts` — окно редактора создаётся с `decorations: true` и `resizable: true`; удалена `initComposeWindowChrome()` и её вызов.
- `src/styles.css` — в окне редактора скрыта наша шапка, оверлей на всю высоту.

## Осталось

- Живая проверка: окно «Новое письмо» — один системный заголовок, ресайз за край окна, кнопки внизу видны.
- Если окажется, что системный ресайз тоже медленный — значит дело точно в перерисовке WebView2, и следующий шаг не про окна: на время ресайза скрывать содержимое карточки (`contain: layout paint` / `content-visibility`), чтобы окно тянулось по пустому фону.
- Если наоборот — перетаскивание за системный заголовок будет раздражать, вернём свою шапку и быстрый драг, оставив системную рамку для ресайза.
