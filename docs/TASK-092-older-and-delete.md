# TASK-092 — Догрузка старых писем и точечное удаление

Дата: 2026-11-15. Версия: 0.46.42.

## Постановка

Из дорожной карты: «пагинация выборки папки» (кэш читается целиком) и «удаление без полной пересборки списка».

## Что выяснилось по пагинации

Пагинация в задуманном виде оказалась не нужна: `fetch_headers` всегда качает только **последние 200** писем папки (`start = total - limit + 1`), значит в кэше физически не бывает больше 200 строк — paginate нечего. Настоящая проблема противоположна: **письма старее двухсот в приложении недоступны вовсе**. Поэтому вместо пагинации сделана догрузка старых писем.

## Решения

**Догрузка старых (TASK-092).**
- Кнопка «Показать более старые» в конце списка, видна когда в кэше меньше писем, чем всего в папке (`folder_stats.total`). Грузит до 200 писем диапазоном `seq` **перед** уже загруженными (`fetch_older`) и дописывает их в конец списка.
- Хранится вместе с остальным кэшем: `store.append_headers()` добавляет строки, не стирая старые (в отличие от `save_folder_sync`, который папку заменяет); индекс FTS и переписок для папки пересобирается целиком — строк немного, зато без расхождений.
- Если старее ничего нет (`min_seq <= 1` или сервер вернул пусто) — тост «Старее писем на сервере нет», кнопка исчезает, когда всё догружено.

**Точечное удаление.**
- `removeMessageRows(uids)`: строки удаляются из DOM, счётчики групп пересчитываются, опустевшие группы убираются; список опустел целиком — обычный рендер с пустым состоянием.
- Исключение — переписки: удаление верхнего письма меняет бейдж и состав цепочки, тут полный рендер дешевле и честнее. Точечный путь используется только для одиночных писем.
- Применено в `commitDelete`, `commitSpam`, `notSpamCurrent`.

## Осталось

- Живая проверка: в папке с письмами нажать «Показать более старые» несколько раз — письма дописываются и остаются после переключения папок; удалить пару писем — список не мигает, счётчики групп честные.
- Догрузка считает «старые» по `seq` внутри папки: после изменения состава папки на сервере порядок остаётся корректным, потому что seq читается заново при каждом вызове.
