# TASK-054 — отправленные в «Отправленные», панель выделения без сдвига

Дата: 2026-11-03. Версия: 0.46.7.

## 1. Как понял задачу

1. **Почему письмо не попадает в «Отправленные».** Нужно найти причину и сделать так, чтобы копия отправленного письма появлялась в папке «Отправленные».
2. **Панель «Выбрано: N» дёргает список.** Сейчас при выделении писем панель встаёт в поток и сдвигает весь список вниз. Нужно, чтобы она появлялась над полем поиска и ничего не смещала.

## 2. Причина по первому пункту

Клиент не сохранял копию вообще:

- `send_mail` (`src-tauri/src/commands/mod.rs:1103`) только вызывал `smtp::send_message` (`src-tauri/src/mail/smtp.rs:182`) и возвращал `Ok(())`;
- IMAP APPEND был реализован только для черновиков (`imap::append_draft`, `src-tauri/src/mail/imap.rs:1179`), функции поиска папки «Отправленные» (`find_sent`) не существовало;
- список писем строится из серверного кэша (`sync_folder`, `src-tauri/src/commands/mod.rs:1041`), поэтому в «Отправленные» попадало только то, что сохранил сам сервер.

Gmail и Outlook сохраняют отправленное автоматически, Mail.ru и Яндекс — нет. Отсюда разное поведение на разных ящиках.

## 3. Что исправлено

### 3.1. Копия отправленного письма

- `imap.rs`: добавлены `find_sent()` (ищет папку по именам `sent`, `sent items`, `sent mail`, `sent messages`, `отправленные`, `отправлено`, с учётом вложенных путей), `autosaves_sent()` (Gmail, Outlook, Office365, Hotmail, Live — пропускаем, чтобы не было дублей) и `append_sent()` (APPEND с флагом `\Seen`).
- `commands/mod.rs`: `send_mail` теперь собирает письмо один раз (`smtp::build_message_full`), отправляет через SMTP и кладёт копию в серверную папку «Отправленные». Возвращает `SendReport { copied, sent_folder, copy_error }`: ошибка копии не отменяет отправку, но доходит до интерфейса.
- `src/main.ts`: после отправки вызывается `syncSentFolder()` — если папка «Отправленные» открыта, список перезагружается, иначе папка тихо синхронизируется в кэш. Если копия не легла, показывается предупреждение с причиной.
- Копия сохраняется и для обычной отправки, и для ответа из строки списка.

### 3.2. Панель выделения

- `#bulk-bar` перенесён внутрь `.list-head` (`index.html`), контейнер получил `position: relative`.
- Панель стала абсолютным оверлеем (`inset: 0`, `z-index: 9`) с плотным фоном, рамкой и тенью: она всплывает поверх строки поиска и закрывает её, пока есть выделение. Список при этом не сдвигается ни на пиксель.
- Для светлой темы — отдельный фон `#fff` и мягкая тень; для тёмной — `#2b2e36` и глубокая тень.
- После снятия выделения панель скрывается, строка поиска снова доступна.

## 6. Что не проверено и риски

- **Живая отправка не выполнялась.** Проверка только компилятором и сборкой: реальный ящик не подключался, APPEND на сервере не подтверждён. Нужна ваша проверка: отправить письмо и посмотреть «Отправленные».
- **Дубли на серверах с автосохранением вне списка.** Пропуск сделан по хостам Gmail/Outlook/Office365/Hotmail/Live. Если ваш сервер тоже сохраняет отправленное сам, но не попал в список, появится дубль — сообщите, добавлю хост.
- **Скорость отправки.** Копия требует отдельного IMAP-соединения и запроса списка папок: отправка станет медленнее на 1–2 секунды.
- **Панель закрывает поиск.** Пока есть выделение, строка поиска недоступна — это следствие выбранного варианта «поверх поиска».
- **Визуальная приёмка** панели в обеих темах — за вами.
