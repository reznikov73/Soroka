# TASK-091 — Цепочки писем

Дата: 2026-11-15. Версия: 0.46.41.

## Постановка

Последний крупный пункт дорожной карты: список плоский, ответы по одной теме висят отдельными строками. Переписка на десять писем занимает десять строк и хоронит остальную почту.

## Решения

- **Ключ переписки считается при синхронизации** и хранится в базе: `messages.msg_id` и `messages.thread_key`. Так список не считает ничего на лету, а группировка работает и на данных из кэша.
- **Алгоритм ключа:** первый Message-ID из `References` (корень переписки) → иначе `In-Reply-To` → иначе собственный `Message-ID` → иначе `uid:<uid>`. Именно корень, а не последний предок: иначе ветка ответов разъезжается на несколько «переписок». Нормализация — без угловых скобок и регистра.
- **В запрос заголовков добавлены** `MESSAGE-ID`, `IN-REPLY-TO`, `REFERENCES` — и в полный, и в упрощённый (для серверов, которые ломаются на BODYSTRUCTURE).
- **В списке** переписка показывается одной строкой — самое новое письмо с бейджем «N». Клик по бейджу раскрывает остальные письма вложенными строками с отступом и вертикальной линией; повторный клик сворачивает. Раскрытые переписки помнятся в `localStorage`.
- **Где работает:** режимы «без группировки» и «по датам» (переписка попадает в группу по дате своего верхнего письма). При группировке по категориям и при активном поиске список остаётся плоским — там сворачивание мешает.
- **Настройка** «Сворачивать переписки» (`appearance.threads`, по умолчанию включена) рядом с маркировкой категорий.
- **Совместимость:** у писем, скачанных до обновления, `thread_key` пустой — они показываются как одиночные, пока папка не пересинхронизируется. Фронтенд к пустому полю устойчив.
