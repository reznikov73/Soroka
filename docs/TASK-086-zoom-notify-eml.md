# TASK-086/087/088 — Масштаб интерфейса, уведомления, экспорт .eml

Дата: 2026-11-14. Версия: 0.46.38.

## Постановка

Три пункта дорожной карты из обсуждения 2026-11-14:

- на 4K-мониторах и мелких ноутбуках размер интерфейса задаёт только системный DPI — увеличить список и текст письма нельзя;
- о новом письме узнаёшь только по точке в трее и числу в заголовке — свёрнутое окно легко пропустить на час;
- письмо нельзя сохранить файлом, чтобы приобщить к делу или переслать как вложение.

## Решения

**Масштаб (TASK-086).** `Ctrl+=` / `Ctrl+-` / `Ctrl+0`, шаг 10 %, диапазон 70–180 %, значение хранится в `localStorage` и применяется во всех окнах при загрузке. Реализовано через CSS `zoom` на `body`: он масштабирует и текст, и отступы, не требуя переверстывать px-размеры; отдельного разрешения Tauri не нужно (в отличие от `webview.setZoom`).

**Уведомления (TASK-087).** `tauri-plugin-notification` подключён на стороне Rust — фронтенду не нужен ни npm-пакет, ни разрешение в capabilities. Уведомление шлётся из `sync_inbox`, когда сервер отдал новые письма: заголовок «Новое письмо» / «N новых письма», в теле — отправитель и тема первого. Если главное окно видимо и в фокусе — уведомление не показывается, чтобы не дублировать и без того видимый список.

**Экспорт .eml (TASK-088).** В окне письма появилась кнопка «Скачать .eml». Файл пишется в «Загрузки»; сырое сообщение тянется с сервера через уже существующий `body::fetch_raw` (в кэше лежат только разобранные части, не оригинал), имя — из темы письма с очисткой опасных символов, при совпадении добавляется «(2)», «(3)».
