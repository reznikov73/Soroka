# TASK-094 — Одно окно чтения вместо окна на каждое письмо

Дата: 2026-11-16. Версия: 0.46.44.

## Постановка

Из плана: «лёгкие дочерние окна» — уменьшить память и время открытия. Перед тем как резать бандл на отдельные точки входа, проверил, из чего вообще складывается стоимость окна.

## Что выяснилось

- Память окна — это **процесс WebView2** (порядка 80–150 МБ), а не бандл: `index.html` весит 49 КБ, скрипт 178 КБ, стили 76 КБ. Разбор и выполнение этого объёма — миллисекунды. Multi-page (отдельные `settings.html`/`compose.html`) сэкономил бы десятки миллисекунд и, может, 20–30 МБ, но потребовал бы распилить `main.ts` на общий модуль и точки входа — большой рефакторинг с риском для всех окон.
- Настоящая утечка была в другом месте: `openMessageWindow` создавал **новое окно на каждое письмо** с уникальным label `msg-<uid>-<время`>. Открыл десять писем — десять процессов и больше гигабайта памяти; закрытые не всегда закрывались (окно чтения с `decorations: true`, но пользователь мог просто переключиться).

## Решение

Окно чтения теперь одно и переиспользуется:

- создаётся с постоянным label `msg-reader`, ссылка хранится в `readerWindow`;
- если окно уже открыто — главное окно шлёт в него событие `reader-show` с данными письма, разворачивает и фокусирует, а не создаёт второе;
- окно чтения слушает `reader-show`, при смене папки перечитывает кэш папки и показывает письмо через тот же `readerShow()`, что и при навигации стрелками;
- когда окно закрывают, `tauri://destroyed` очищает ссылку — следующее открытие создаст его заново;
- если окно с таким label осталось от прошлой сессии и создание падает, событие всё равно уходит в него.

## Сделано

- `src/main.ts` — `readerWindow`, переписан `openMessageWindow()`, слушатель `reader-show` в `initReaderWindow()`.

## Осталось

- Живая проверка: двойной клик по одному письму, затем по другому — должно открываться то же окно с новым письмом; закрыть окно и открыть снова — создаётся заново.
- Решение по «лёгким окнам»: multi-page отложен как невыгодный (см. выше). Если память всё равно будет мешать — следующий шаг не резать бандл, а уменьшать число окон: например, настройки и редактор показывать оверлеями в главном окне вместо отдельных процессов.
